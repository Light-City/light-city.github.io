    Сборка проектов C++ с помощью Meson¶

    В последнее время, работая с рядом открытых проектов, я обнаружил, что все они используют сборку meson+ninja, отказавшись от CMake и Makefile; в этой статье мы познакомимся с Meson — от установки до написания полного meson-проекта.

    Итак, переходим к сути.

    1. Установка Meson¶

    https://github.com/mesonbuild/meson

    Meson можно получить через PyPi, поэтому для установки подойдёт pip3 install meson. В разных системах используйте правильную команду pip — обязательно pip версии Python 3.

    При желании можно установить локально стандартной Python-командой:

    python3 -m pip install meson
    Для сборки с Ninja сам Ninja можно скачать со страницы релизов Ninja на GitHub или через PyPi:

    python3 -m pip install ninja
    Больше информации об установке Meson build читайте на официальном сайте Meson ниже.

    https://mesonbuild.com/Getting-meson.html

    2. Meson Vs Cmake¶

    Раз все пользуются CMake, зачем нужен Meson и каковы их сильные и слабые стороны?

    Что касается производительности, Meson обычно славится высокой скоростью сборки. Meson спроектирован так, чтобы оптимизировать скорость сборки, и особенно хорош в инкрементальных сборках. Meson использует систему сборки Ninja как бэкенд по умолчанию, а Ninja сам по себе известен быстротой и эффективностью.

    Для сравнения: скорость сборки CMake может зависеть от размера проекта, особенно в крупных проектах. CMake использует разные генераторы (например, Makefile), и производительность разных генераторов тоже может различаться.

    Разумеется, можно использовать CMake + Ninja, чтобы повысить скорость компиляции.

    Если смотреть на Meson с точки зрения открытых проектов, сфера его применения очень обширна: PostgreSQL, QEMU, GNOME Software, GTK+ и т.д.

    https://mesonbuild.com/Users.html

    2.1 Преимущества и недостатки Meson¶

    1.Преимущества

    • Основан на Python, прост в использовании
    • Поддерживает кросс-компиляцию
    • Все объекты строго типизированы: поскольку объекты — это сущности вроде 'dependency', 'include directory' и т.д., ошибки строковых подстановок почти невозможны.
    • Очень удобно подключать сторонние библиотеки
    • Очень-очень быстрый, особенно при инкрементальной сборке.
    • Документация лучше cmake в n раз.

    http://mesonbuild.com

    2.Недостатки

    • Возможно, менее зрелый, чем CMake
    • Зависимости Python3 + Ninja
    • Генераторы проектов, поддержка Meson в IDE хуже, чем CMake
    • поддержка vscode
    • https://github.com/mesonbuild/vscode-meson
    • Ограниченное число доступных модулей
    • не-meson-проекты нужно самостоятельно отправлять в wrapdb
    • https://mesonbuild.com/Wrapdb-projects.html

    2.2 Преимущества и недостатки CMake¶

    1.Преимущества

    • Дружелюбная поддержка IDE, довольно удобно для командной работы
    • Зрелый, практически стал стандартом C++-проектов

    2.Недостатки

    • Трудности с кросс-компиляцией
    • Скорость компиляции относительно невысокая

    3. Meson WrapDB¶

    Поскольку googletest — не meson-проект, как подключить его через meson?

    Аналогично используются grpc, abseil-cpp.

    Здесь сначала нужно ввести WrapDB: Meson WrapDB — это компонент системы сборки Meson, предназначенный для управления и предоставления файлов описания сборки сторонних проектов, обычно называемых «wrap»-файлами. Эти wrap-файлы содержат информацию, необходимую для настройки и сборки стороннего проекта, чтобы его можно было легко интегрировать в другие проекты, использующие систему сборки Meson.

    искать сторонние библиотеки можно командой search или на сайте ниже.

    https://mesonbuild.com/Wrapdb-projects.html#meson-wrapdb-packages

    Возьмём для примера использование gtest:

    • Поиск gtest

    meson wrap search gtest
    Если команда вернула имя упакованного проекта, можно переходить к следующему шагу:

    • Создаём в своём проекте каталог subprojects и устанавливаем gtest через install

    mkdir -p subprojects
meson wrap install gtest
    На этом все сторонние библиотеки, от которых зависит ваш проект, уже установлены в каталоге subprojects.

    ➜  gtest_div tree -L 1 subprojects
subprojects
├── gtest.wrap
    При этом будет сгенерирован gtest.wrap, содержимое которого включает следующее.

    Внимание: этот файл создаётся после install выше; рекомендуется его не изменять.

    [wrap-file]
directory = googletest-1.14.0
source_url = https://github.com/google/googletest/archive/refs/tags/v1.14.0.tar.gz
source_filename = gtest-1.14.0.tar.gz
source_hash = 8ad598c73ad796e0d8280b082cebd82a630d73e73cd3c70057938a6501bba5d7
patch_filename = gtest_1.14.0-1_patch.zip
patch_url = https://wrapdb.mesonbuild.com/v2/gtest_1.14.0-1/get_patch
patch_hash = 2e693c7d3f9370a7aa6dac802bada0874d3198ad4cfdf75647b818f691182b50
source_fallback_url = https://github.com/mesonbuild/wrapdb/releases/download/gtest_1.14.0-1/gtest-1.14.0.tar.gz
wrapdb_version = 1.14.0-1

[provide]
gtest = gtest_dep
gtest_main = gtest_main_dep
gmock = gmock_dep
gmock_main = gmock_main_dep

    4. Как написать meson-проект?¶

    Переходим к практике: как написать meson-проект?

    Ниже на примере теста деления a/b — небольшой проект с модульным тестированием через gtest.

    4.1 Написание кода¶

    double divide(double a, double b);
    .h и .cc кладём в каталог src:

    src
├── division.cc
└── division.h
    Затем на том же уровне создаём каталог test.

    test
└── division_test.cc

    4.2 Управление meson-проектом¶

    Добавляем в корень проекта файл meson.build со следующим содержимым:

    project('gtest_div', 'cpp')
gtest_proj = subproject('gtest')
gtest_dep = gtest_proj.get_variable('gtest_main_dep') 
div_src = files('src/division.cc')
tests_src = files('test/division_test.cc')
e = executable(
    'division_test',
    tests_src + div_src, 
    dependencies : [ gtest_dep],
    override_options : ['cpp_std=c++14']
)
# https://mesonbuild.com/Unit-tests.html#testing-tool
test('this is a division test', e)
    Видно, что это содержимое практически совпадает с синтаксисом python; тем, кто знает python, такой код даётся очень легко; здесь подробнее разберём важные части выше.

    • Подключение сторонних библиотек

    Например: подключённый сторонний проект называется gtest, вот так:

    project('gtest', 'cpp',
  version : '1.14.0',
  default_options : ['cpp_std=c++14'],
  license : 'bsd')
    Тогда через subproject можно получить этот project, а затем через gtest_proj.get_variable — информацию о зависимостях gtest; например, в googletest это объявлено так:

    gtest_main_dep = declare_dependency(
    include_directories : gtest_incdir,
    sources : [gtest_libsources, gtest_mainsources],
    dependencies : dependency('threads')
)
    - executable

    executable очень похож на add_executable в cmake — генерирует исполняемый файл division_test.

    • test

    Синтаксис модульного теста:

    e = executable('prog', 'testprog.c')
test('name of test', e)
    Можно использовать meson test или ninja test; после выполнения будет создан лог тестирования, находящийся по адресу:

    build/meson-logs/testlog.txt

    Можно использовать две команды ниже, первый вариант:
